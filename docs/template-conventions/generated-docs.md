# Generated Documentation Conventions

Defines the documentation structure that every template generates in output projects.

## CLAUDE.md (+ AGENTS.md symlink)

Always generated. AGENTS.md is always a symlink to CLAUDE.md.

CLAUDE.md answers **"how do I work in this codebase?"** — not "what is this project?" (that's the README).

### Structure

```markdown
# CLAUDE.md

<one-line description: what this project is, language, framework>

## Quick Reference

| Command | Purpose |
| ------- | ------- |
| `just fmt` | Check formatting |
| `just lint` | Check linting |
| `just gate` | Fast pre-push check |
| ... | (all justfile targets) |

## Project Structure

<brief map of directories and what each is for>

## Key Conventions

<3-5 bullets: layering rules, patterns, things NOT to do>

## More Information

- `docs/architecture.md` — read before adding new modules or changing the layering
- `docs/development.md` — read for environment setup, debugging, or deployment
- `docs/api.md` — read before adding or modifying API endpoints (service/web only)
```

### Principles

- Concise enough to fit in agent context without truncation.
- Quick Reference is the most-used section — agents look here first.
- Links to `docs/` include *when* to read them, not just what they contain.

## README.md

Always generated. Answers **"what is this and how do I set it up?"**

### Sections

```markdown
# project_name

project_description

## Getting Started

## Development

## Testing

## Deployment (service/web/agent only)

## Architecture (link to docs/architecture.md)

## Contributing

## License
```

## docs/ Directory

### Progressive Information Discovery

Documentation is layered so agents read the minimum needed and drill deeper only when required.

| Layer | File | When to read |
| ----- | ---- | ------------ |
| 0 | `CLAUDE.md` | Always loaded. Enough to make changes. |
| 1 | `README.md` | Understanding the project, initial setup. |
| 2 | `docs/architecture.md` | Before adding modules, changing structure, or modifying layering. |
| 2 | `docs/development.md` | Environment setup, debugging, common tasks, deployment. |
| 3 | `docs/api.md` | Before adding or modifying API endpoints (service/web only). |
| 3 | `docs/adrs/` | Before proposing architectural changes. |

### Structure

```
docs/
  architecture.md        # system design, layering, data flow, key patterns
  development.md         # environment setup, debugging, common tasks
  api.md                 # API reference (service/web/agent only)
  adrs/                  # architecture decision records
  technical/             # optional: TDDs, technical specs
    .gitkeep
  product/               # optional: PRDs, product briefs
    .gitkeep
```

### Copier Questions

| Variable | Type | Default | Description |
| -------- | ---- | ------- | ----------- |
| `include_technical_docs` | bool | false | Create `docs/technical/` for TDDs and technical specs |
| `include_product_docs` | bool | false | Create `docs/product/` for PRDs and product briefs |

### Content Guidelines

- `architecture.md` — generated with initial content based on the template's layering and patterns. Should be maintained as the project evolves.
- `development.md` — generated with setup instructions, prerequisites, and how to run/test/deploy.
- `api.md` — generated with a skeleton for service/web types. Omitted for lib/cli.
- `docs/technical/` and `docs/product/` — created with `.gitkeep` only. These are for the project team to populate.

## Frontend Composition Workflow

For `-web` templates (except `typescript-web` which uses Next.js), the frontend is **not** generated by the `-web` template itself. Instead:

1. The `-web` template generates:
   - The backend (routers, controllers, services, etc.)
   - Glue: docker-compose frontend service, `-fe` justfile targets, proxy config
   - A stub `src/<package_name>/web/frontend/` with a README explaining the next step

2. The agent (or user) runs `frontend-react` template into the frontend directory:
   ```sh
   copier copy /path/to/templates/frontend-react src/<package_name>/web/frontend/
   ```

3. The generated CLAUDE.md and `docs/development.md` document this two-step workflow.

This avoids duplicating the frontend scaffold across `-web` templates and keeps `frontend-react` as a single source of truth.
